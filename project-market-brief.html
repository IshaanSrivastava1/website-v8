AI Market Brief Agent

Python · Claude API · Tool Use · Agent Loop · Web Search · GitHub Actions

Built August 2026 · retired October 2026 along with the gold arbitrage tracker it was part of

View the archived tracker →

What I Built

  • A "What's going on today" section at the top of my gold arbitrage tracker, written by an AI agent instead of a template. The tracker scanned every open gold-price market on Polymarket and Kalshi and flagged contracts priced inconsistently against each other — it showed the numbers well but couldn't explain them.
  • The agent was given three tools and decided for itself which to use and when it had enough to write: one returned the arbitrage opportunities found in the current scan, one returned the normalised contract prices from both platforms, and a third ran a web search on Anthropic's own infrastructure, so there was no second API key or news provider to manage.
  • It typically checked the market data first, searched the news only when something in the numbers needed explaining, then wrote a few paragraphs on what stood out, citing its sources — rendered as links under the brief.

How It Worked

  • The loop: the model picked a tool, the code ran it, the result went back, and it repeated until the model stopped asking. That loop is the whole idea of an agent.
  • Two calls by design: the agent researched and wrote prose, then a second, cheaper call reformatted that prose into a headline, body, and source list for the page.
  • Cost control: the tracker was scheduled every 30 minutes, and regenerating the brief on every scan would mostly have rewritten the same paragraph. It regenerated only when the set of detected opportunities changed, or when the cached brief passed six hours old — a handful of model calls a day instead of 48.
  • Fail-open: if the model was unavailable, the previous brief was shown marked as possibly out of date, or the section removed itself. A failed brief never failed the page build — 26 unit tests covered the caching and fallback logic.

What I Learned

  • Tools should hand over data you already have. The tools were thin wrappers around data the tracker had just fetched, not fresh API calls — so the agent never doubled the slowest part of the build or saw numbers different from the page.
  • Separate thinking from formatting. Rather than one call that researched, used tools, and emitted strict JSON at once, a free-form research loop followed by a schema-enforced formatting call kept each step simple and easy to debug.
  • Gate model calls on what changed. Fingerprinting the opportunity set and skipping the call when it hadn't moved was the single biggest cost lever — from 48 model calls a day to a handful.
  • Be specific about what you want cited. A citation that only names a publication can't become a link. Requiring the full URL right after each claim is what made sources renderable on the page.
  • Tell the model a quiet day is a valid answer. Most scans found nothing, so the prompt explicitly allowed "nothing unusual today". The briefs that followed called tenth-of-a-cent edges what they were — rounding noise — instead of inventing a story.
  • Fail-open needs a signal. When the API key was invalidated in September, the page kept building exactly as designed — and quietly served a weeks-old brief marked "may be out of date". It degraded gracefully, but nothing alerted me that it had.

Thesis

I built this to learn how AI agents actually work, alongside a second project (the job-fit scoring agent) that did the same thing in a different shape. This one was the fuller version: a genuine tool-use loop where the model decided what to check rather than following a fixed script.

The honest limitation: the agent described and explained, it did not advise. The page said so explicitly, and the brief was written to avoid predictions or trade recommendations.
