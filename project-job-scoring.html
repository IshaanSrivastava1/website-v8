AI Job-Fit Scoring Agent

Python · Claude API · Structured Outputs · Prompt Caching · GitHub Actions · Discord

Built August 2026 · retired October 2026 — the job-alert watcher it sat inside is still running, without the AI layer

View the code as built →

What I Built

  • I already ran a job-alert watcher that polls the public Greenhouse and Lever job-board APIs across roughly 90 companies every few minutes via GitHub Actions and pushes analyst-role matches to a private Discord channel.
  • A keyword filter on "analyst" was matching sales analysts, security analysts, and senior roles I'm not qualified for, so most alerts were noise. I added a scoring layer: before each new posting was sent, its full description went to Claude along with a profile of my background, and it returned a fit score from 1 to 10, a one-sentence reason, a list of red flags, and whether the seniority was under, over, or a match.
  • Every posting was still sent — nothing was filtered out. The score rode along in the Discord message, with the border colour-coded green, amber, or red, and red flags like "no visa sponsorship" listed underneath.

How It Worked

  • Structured outputs: the response shape was enforced by the API against a JSON schema, so there was no parsing or retry logic for malformed replies.
  • Prompt caching: my profile was identical on every call, so it was sent as a cached block — about 2,800 tokens were read from cache per call and only around 220 billed at full price, roughly $0.002 per job scored.
  • Fail-open: if the API key was missing or the call failed, the alert still went out, just without a score. Scoring could never break the alerting it sat inside — 22 unit tests covered those degraded paths.
  • The profile itself was supplied as a GitHub Actions secret rather than a committed file, since the repository is public.

What I Learned

  • Start at the lowest rung of the agent ladder. This didn't need tools or a loop — one structured call answered the question. The market brief agent, built alongside it, needed a full tool-use loop; matching the design to the problem kept this one small and cheap.
  • Let the API enforce the output. A schema-enforced response removed a whole category of code: no JSON parsing, no retries, no malformed-reply handling.
  • Cache what doesn't change. Most of each request was the same profile text; caching it made per-call cost almost entirely the posting itself.
  • Fail-open works — and hides failures. When the API key was invalidated in September, alerts kept flowing exactly as designed. But because nothing broke, nothing told me: scoring had silently stopped for weeks. Graceful degradation needs a signal that it's happening.
  • Weigh recurring cost against the value it adds. I retired the scoring layer in October 2026 because its ongoing token spend wasn't something I needed. An AI step should keep earning its running cost, not just be impressive.

Thesis

I built this to learn how AI agents actually work, alongside a second project (the market brief agent) that did the same thing in a different shape. This one was the simpler end of that spectrum: a single structured API call dropped into a workflow that already worked, not a full tool-use loop.

The honest limitation: a score is only as good as the profile it's compared against — a job the model scored a 4 was a judgement, not a fact.
